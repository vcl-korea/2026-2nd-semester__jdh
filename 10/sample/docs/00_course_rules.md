# 수업 개발 조건 — 이 PC에서 만들 수 있는 것과 나중에 스스로 할 것

이 파일은 10~13회에 AI가 코드를 고치기 전에 `PRD.md`·`09_development_plan.md`와 함께 먼저 읽는 수업 조건이다.
AI는 학생의 아이디어를 바로 코드로 만들지 않고, 먼저 이 조건 안에서 어떻게 만들지 확인한다.
원칙은 하나다. **학생이 원한 기능은 이 PC의 Next.js에서 돌릴 수 있으면 수업에서 만든다.**
실행 환경이 달라야 하는 기능은 13회 뒤에 학생이 스스로 하고, 지금 기술로도 어려운 기능은 사람이 대신 하거나 흉내 내는 방법으로 바꾼다.

## 1. 수업 프로젝트의 기본 조건

- 만드는 사람은 웹서비스를 처음 만드는 중·고등학생이다.
- 학생은 코드를 처음부터 쓰지 않는다. AI가 만든 결과를 실행하고, 확인하고, 고쳐 달라고 요청한다.
- 10~13회에는 선생님이 나눠 준 표준 프로젝트(Next.js) `10` 폴더 하나에서 만든다. 학교 PC에서 `npm run dev`로 켜고 브라우저로 쓴다.
- 화면과 서버를 다른 프로젝트로 나누지 않는다. 포트·DB 위치는 표준 프로젝트에 정해져 있다.
- 학생은 OpenCode의 plan 모드에서 어떻게 고칠지 설명을 듣고, 확인한 뒤 build 모드로 바꿔 「진행해」라고 한다.
- 새 패키지가 필요하면 AI가 패키지 이름과 쓰는 이유를 먼저 설명하고, 학생이 「진행해」라고 하면 설치한다.
- 핵심 기능은 한 가지다. 다른 기능은 핵심 기능이 된 뒤에 개발 계획 5항의 순서대로 붙인다.
- 모든 서비스는 핵심 기능을 쓰면 생기는 의미 있는 기록을 하나 이상 SQLite에 저장하고, 다시 보여 준다.
- 표는 한 개로 시작해도 된다. 표 수를 늘리려고 쓸모없는 기록을 만들지 않는다.
- 실제 개인정보와 민감한 정보를 쓰지 않는다.

## 2. 바로 만들 수 있는 기능

표준 프로젝트에 들어 있는 것만으로 만든다.

- 글자·숫자·날짜 입력, 항목 고르기, 버튼
- 입력 확인, 계산·분류·정렬·검색
- 결과·안내·목록 보여 주기
- SQLite에 기록 저장하고 다시 불러오기
- 브라우저 안의 2D 그림과 움직임
- 새로고침하거나 다시 켠 뒤 결과 확인

## 3. 준비하면 만들 수 있는 기능 (이 PC에서 된다)

패키지·파일·자료를 준비하면 이 PC에서 된다. 개발 계획 5항에서 몇 회에 붙일지 정한다.

- 이 PC 안의 회원가입·로그인 — 비밀번호는 7-2처럼 단방향 암호화해 저장한다. 새 패키지 없이 Node 내장 `node:crypto`를 쓴다
- 파일 올리기(사진·문서) — `data/uploads`에 두고 SQLite에는 파일 정보만 적는다
- 3D 그림·게임(three.js), 사진 속 글자 인식(tesseract.js)처럼 패키지가 필요한 기능
- 소리·음악 재생 — 음원 파일을 직접 준비한다(저작권이 괜찮은 것)
- 유튜브 영상·지도 넣기(퍼가기)
- 서비스를 켜 둔 동안의 브라우저 알림
- 친구와 하는 대결·채팅 — **같은 PC에서** 차례로 하거나 브라우저 창 두 개로 한다

## 4. 수업에서는 흉내 내는 기능 — 외부 AI

ChatGPT·Gemini 같은 외부 AI는 PC에서 연결할 수는 있지만, 약관상 18세 미만이 쓰는 서비스에 쓸 수 없다.
그래서 수업에서는 **수업용 프로토타입**으로 만든다.

- AI가 하려던 일을 규칙·키워드·준비한 예시 답으로 흉내 낸다.
- 나중에 진짜 AI를 붙일 수 있게, 그 일을 맡는 API를 하나로 모아 둔다(예: `/api/answer`).
- 화면과 문서에 「수업용 프로토타입 — 진짜 AI가 아니다」라고 밝힌다. 된 것처럼 말하지 않는다.
- 학생 개인 API 키를 만들거나 프로젝트에 넣지 않는다.

## 5. 13회 뒤에 스스로 할 기능 — 실행 환경이 다르다

이 PC의 Next.js가 아닌 다른 환경이 있어야 하는 기능이다. 수업에서는 만들지 않고, 개발 계획 6항 「수업 뒤로 미룬 것」에 필요한 실행 환경과 함께 남긴다.

- 휴대폰 앱, 잠금화면·홈 화면 위젯
- 여러 기기에서 이어 쓰기(동기화), 다른 기기의 친구와 실시간 대결·채팅
- 인터넷에 공개하기(배포·터널), 외부 DB·클라우드 저장
- Google·Kakao 로그인
- 이메일·문자·푸시 알림
- 결제·광고

## 6. 지금 기술로도 어려운 기능 — 전문가도 초안 수준까지만 된다

실행 환경을 바꿔도 해결되지 않는다. 전문 개발자와 실제 서비스도 아직 초안 수준까지만 해내는 기술 한계다.

- 예: 커버 영상의 소리를 듣고 기타 타브 악보를 자동으로 만들기
- 예: 사진에서 형광펜으로 표시한 단어만 골라내기
- 수업에서는 **사람이 대신 하는 단계**(학생이 직접 고르기·고치기)를 넣거나, 규칙·예시로 흉내 낸 수업용 프로토타입으로 바꾼다.
- 사용자가 얻으려던 결과는 지키고, 만드는 방법만 바꾼다. 원래 기능은 개발 계획 6항에 이유와 함께 남긴다.
- 판정할 때는 근거(비슷한 실제 서비스·기술 이름, 가장 어려운 부분)를 함께 말한다. 모르면 모른다고 한다.

## 7. 수업에서 하지 않는 것

- 실제 개인정보·민감한 정보 저장
- 유료 서비스와 유료 키
- 다른 웹사이트의 내용을 허락 없이 긁어 오기(크롤링)

## 8. 판정하는 방법

기능마다 다음 다섯 가지 중 하나로 판정하고, 이유를 쉬운 말로 적는다. 이것은 **수업 조건**에 따른 판정이다. 9-1의 `> [점검 3]` 주석은 수업과 상관없이 지금 기술로 되는지만 본 것이고, 9-2 개발 계획 1·6항이 이 조건으로 「수업에서 만든다 · 수업에서는 흉내 낸다 · 13회 뒤 스스로」를 정했다.

1. **바로 구현 가능** — 표준 프로젝트에 있는 것만으로 만든다.
2. **준비하면 구현 가능** — 이 PC에서 된다. 필요한 패키지·파일·자료를 적고, 몇 회에 붙일지 정한다.
3. **수업용 프로토타입** — 외부 AI가 필요하다. 수업에서는 규칙·예시 답으로 흉내 내고, 진짜 AI는 13회 뒤 스스로 한다.
4. **13회 뒤 스스로** — 다른 실행 환경이 필요하다. 어떤 환경이 필요한지 적는다.
5. **지금 기술로도 어려움** — 전문가도 아직 초안 수준까지만 된다. 사람이 대신 하는 단계나 흉내 내는 방법을 제안한다.

기능을 몰래 다른 기능으로 바꾸거나, 작동하지 않는 기능을 된 것처럼 말하지 않는다.
기능이 커서 13회까지 다 못 만들 것 같으면, 사용자가 얻으려던 결과를 먼저 말하고 개발 순서를 나눠 제안한다.
