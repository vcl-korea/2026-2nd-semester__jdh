1. 기본 조건1. 基本条件9-0

이 PC에서 돌릴 수 있으면 수업에서 만든다能在这台电脑上跑起来，就在课上做 핵심核心

이 자료는 9~13회에 AI가 내 PRD보다 먼저 읽는 수업 조건입니다. 9회에 06 폴더에 더한 00_course_rules.md와 내용이 같습니다. 원칙은 하나입니다. 내가 원한 기능은 이 PC의 Next.js에서 돌릴 수 있으면 수업에서 만듭니다. 실행 환경이 달라야 하는 기능만 13회 뒤에 스스로 합니다.这份资料是第 9~13 次课 AI 比我的 PRD 先读的课堂条件，和第 9 次课加进 06 文件夹的 00_course_rules.md 内容一样。原则只有一条：自己想要的功能，只要能在这台电脑的 Next.js 上跑起来，就在课上做。只有需要别的运行环境的功能，才在第 13 次课之后自己去做。

  • 9회에는 코드·화면·프로젝트 파일을 만들지 않습니다. 실제 개발은 10회부터입니다.第 9 次课不生成代码、画面和项目文件。真正的开发从第 10 次课开始。
  • 10회부터는 선생님이 나눠 주는 표준 프로젝트(Next.js) 하나에서 만듭니다. 학교 PC에서 켜고 브라우저로 씁니다.从第 10 次课起，在老师发的一个标准项目（Next.js）里做。在学校电脑上启动，用浏览器来用。
  • 새 패키지가 필요하면 AI가 이름과 이유를 먼저 설명하고, 내가 「진행해」라고 하면 설치합니다.需要新的包时，AI 先说明包名和理由，我说“继续”后再安装。
  • 핵심 기능은 한 가지입니다. 다른 기능은 핵심 기능이 된 뒤에 개발 순서대로 붙입니다.核心功能只有一个。其他功能等核心功能做好后，按开发顺序再加。
  • 모든 서비스는 핵심 기능을 쓰면 생기는 의미 있는 기록을 SQLite에 저장하고 다시 보여 줍니다.每个服务都要把使用核心功能时产生的有意义的记录存进 SQLite，并再次显示出来。
  • 실제 개인정보와 민감한 정보, 유료 서비스는 쓰지 않습니다.不使用真实的个人信息、敏感信息和付费服务。
2. 이 PC에서 되는 것2. 这台电脑上能做的9-0

바로 되는 기능과 준비하면 되는 기능马上能做的功能和准备后能做的功能 핵심核心

왼쪽은 표준 프로젝트에 들어 있는 것만으로 만드는 기능입니다. 오른쪽은 패키지·파일·자료를 준비하면 이 PC에서 되는 기능입니다. 오른쪽 기능은 개발 계획에 무엇을 준비하고 몇 회에 붙일지 적습니다.左边是只用标准项目里已有的东西就能做的功能。右边是准备好包、文件或资料后，在这台电脑上就能做的功能。右边的功能要在开发计划里写清准备什么、第几次课加上。

바로 만들 수 있는 기능马上能做的功能
  • 글자·숫자·날짜 입력, 항목 고르기, 버튼输入文字·数字·日期，选择项目，按钮
  • 입력 확인, 계산·분류·정렬·검색检查输入，计算·分类·排序·搜索
  • 결과·안내·목록 보여 주기显示结果·提示·列表
  • SQLite에 기록 저장하고 다시 불러오기把记录存进 SQLite 再调出来
  • 브라우저 안의 2D 그림과 움직임浏览器里的 2D 图形和动画
준비하면 만들 수 있는 기능准备后能做的功能
  • 이 PC 안의 회원가입·로그인 (비밀번호는 7-2처럼 단방향 암호화)这台电脑内的注册·登录（密码像 7-2 那样单向加密）
  • 사진·문서 올리기上传照片·文件
  • 3D 그림·게임, 사진 속 글자 읽기 (새 패키지)3D 图形·游戏，读出照片里的文字（新的包）
  • 소리·음악 재생, 유튜브 영상·지도 넣기播放声音·音乐，嵌入 YouTube 视频·地图
  • 서비스를 켜 둔 동안의 브라우저 알림服务开着时的浏览器通知
  • 친구와 대결·채팅 — 같은 PC에서 차례로, 또는 창 두 개로和朋友对战·聊天 — 在同一台电脑上轮流，或开两个窗口
3. 흉내와 나중3. 模拟与以后9-0

외부 AI는 흉내 내고, 다른 환경이 필요한 것은 13회 뒤에外部 AI 先模拟，需要别的环境的放到第 13 次课之后

ChatGPT·Gemini 같은 외부 AI는 PC에서 연결할 수는 있지만, 약관상 18세 미만이 쓰는 서비스에 쓸 수 없습니다. 그래서 수업에서는 규칙·예시 답으로 흉내 낸 수업용 프로토타입을 만듭니다. 휴대폰이나 다른 기기가 있어야 하는 기능은 13회 뒤에 스스로 합니다.ChatGPT·Gemini 这类外部 AI 在电脑上能连上，但按使用条款，不能用在未满 18 岁的人使用的服务里。所以课上用规则·示例回答做出模拟的课堂用原型。需要手机或其他设备的功能，在第 13 次课之后自己做。

수업용 프로토타입 — 외부 AI课堂用原型 — 外部 AI
  • AI가 하려던 일을 규칙·키워드·예시 답으로 흉내 낸다用规则·关键词·示例回答模拟 AI 要做的事
  • 나중에 진짜 AI를 붙이도록 그 일을 API 하나에 모아 둔다把这件事集中到一个 API 里，方便以后接上真 AI
  • 화면과 문서에 「진짜 AI가 아니다」라고 밝힌다在画面和文件里写明“不是真的 AI”
  • 학생 API 키를 만들거나 넣지 않는다不申请也不放入学生自己的 API 密钥
13회 뒤 스스로 — 실행 환경이 다르다第 13 次课后自己做 — 运行环境不同
  • 휴대폰 앱, 잠금화면·홈 화면 위젯手机 App，锁屏·主屏幕小组件
  • 여러 기기 동기화, 다른 기기의 친구와 실시간 대결多设备同步，和别的设备上的朋友实时对战
  • 인터넷에 공개하기, 외부 DB·클라우드发布到互联网，外部数据库·云
  • Google·Kakao 로그인, 이메일·문자·푸시 알림Google·Kakao 登录，邮件·短信·推送通知
  • 결제·광고支付·广告
수업에서 하지 않는 것课上不做的事

실제 개인정보 저장, 유료 서비스와 유료 키, 다른 웹사이트 내용을 허락 없이 긁어 오기는 어떤 판정이든 하지 않습니다.保存真实个人信息、付费服务和付费密钥、未经允许爬取别的网站内容，不管怎么判定都不做。

4. 만드는 방법4. 做法9-0

원한 결과는 지키고, 이 PC에서 되는 만큼 만든다守住想要的结果，在这台电脑上能做多少就做多少 핵심核心

기능을 몰래 다른 기능으로 바꾸거나, 작동하지 않는 기능을 된 것처럼 말하지 않습니다. 먼저 사용자가 그 기능으로 얻으려던 결과를 말하고, 이 PC에서 되는 부분은 만들고, 안 되는 부분만 흉내 내거나 13회 뒤로 남깁니다.不要偷偷换成别的功能，也不要把跑不起来的功能说成做好了。先说清用户想通过它得到的结果，在这台电脑上能做的部分就做，做不了的部分才模拟，或留到第 13 次课之后。

원래 아이디어原来的点子수업에서 만드는 방법课上的做法13회 뒤 스스로第 13 次课后自己做
AI가 질문에 답한다AI 回答问题키워드·규칙으로 답을 고르는 수업용 프로토타입用关键词·规则选回答的课堂用原型진짜 AI 연결接上真 AI
사진 속 단어를 읽어 모은다读出照片里的单词并收集사진 올리기 + 글자 읽기 패키지. 모를 단어는 내가 고른다上传照片 + 读文字的包。不认识的词由我来挑휴대폰으로 찍자마자 올리기用手机一拍就上传
로그인해서 여러 기기에서 쓴다登录后在多台设备上用이 PC 안의 회원가입·로그인这台电脑内的注册·登录여러 기기 동기화多设备同步
친구와 실시간으로 대결한다和朋友实时对战같은 PC에서 창 두 개로 대결하고 기록을 순위로同一台电脑开两个窗口对战，记录按排名看다른 기기끼리 대결不同设备之间对战
위젯으로 오늘 할 일을 알려 준다用小组件提醒今天要做的事첫 화면의 오늘 카드 + 브라우저 알림首页的今日卡片 + 浏览器通知휴대폰 위젯手机小组件

5. 판정5. 判定9-0

기능마다 넷 중 하나로 판정한다每个功能都判定为四种之一

9-2에서 AI는 사용자 흐름에 나오는 기능마다 아래 넷 중 하나로 판정하고 이유를 씁니다. 기능이 커서 4회 안에 다 못 만들 것 같으면 개발 순서를 나눠 제안합니다. 판정한 뒤에도 내가 확인하기 전에는 코드를 만들지 않습니다.9-2 时，AI 会把用户流程里出现的每个功能判定为下面四种之一，并写出理由。功能太大、4 次课做不完的话，就把开发顺序拆开来提。判定之后，在我确认之前也不生成代码。

판정判定뜻意思
바로 구현 가능马上可以实现표준 프로젝트에 있는 것만으로 만든다.只用标准项目里已有的东西来做。
준비하면 구현 가능准备后可以实现이 PC에서 된다. 필요한 패키지·파일·자료를 적고, 몇 회에 붙일지 정한다.这台电脑上能做。写下需要的包·文件·资料，定好第几次课加上。
수업용 프로토타입课堂用原型외부 AI가 필요하다. 수업에서는 규칙·예시 답으로 흉내 낸다.需要外部 AI。课上用规则·示例回答来模拟。
13회 뒤 스스로第 13 次课后自己做다른 실행 환경이 필요하다. 어떤 환경이 필요한지 적는다.需要别的运行环境。写下需要什么环境。
AI가 지킬 순서AI 要遵守的顺序

사용자 흐름을 먼저 이해한다 → 각 기능을 판정한다 → 준비할 것과 개발 순서를 제안한다 → 학생이 흐름과 범위를 확정한 뒤에만 개발 순서를 쓴다.先理解用户流程 → 判定每个功能 → 提出要准备的东西和开发顺序 → 学生确定流程和范围之后，才写开发顺序。
